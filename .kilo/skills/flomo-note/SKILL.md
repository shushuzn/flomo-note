# flomo 卡片笔记（云端）

本文件是执行细则唯一来源；项目总则见 AGENTS.md，两者不重复。体系：flomo 极简卡片 + 标签聚合，笔记只存云端，本地不落任何卡片正文；本目录仅存本技能、AGENTS.md、.mcp.json。

## 执行铁律（动手前先对照，违背即事故）

1. **授权分类**：memo_search、tag_tree、memo_batch_get、memo_recommended、get_format_guide、get_tag_guide、memory_context、memory_user、webfetch、websearch 可直接做；memo_create、memo_update、tag_rename 必须先展示内容并等明确同意，绝不静默写云端。无 memo_delete 能力，删除由用户在 App 手动做。
2. **写前必抓取**：带来源 URL 的 memo，写入前该 URL 必须已真实抓取并基于实际内容写作；未抓取/失败/凭链接猜一律禁止写云。纯想法无来源 memo 不受限但不得虚构来源，生造 URL 视同编造。
3. **脚本传参**：调 flomo 一律走 `flomo_client.py --file <路径>` 从文件读 JSON（PowerShell 中文环境会把内联引号转全角致解析失败），绝不用内联 JSON。
4. **查重阻塞**：写云前必须查重，并显式报告结论（命中什么/无重复），不得用"已查重"三字敷衍。
5. **复盘落地**：复盘建议必须可落地，凡文档改动回复须附真实 commit hash（或明示"未提交"），绝不口头声称"已推送"而实际没做。
6. **组织靠标签**：卡的组织只靠标签承载，卡间关系仅在查重/合并时按需判断，不作为复盘建议主动提出。
7. **来源纯净**：来源行不加任何注释（如"经搜索核验"），正文不加可信度/来源强度标注。

## 理念

- 笔记在云端：每张卡即一条 flomo memo，经 memo_create 直写账号；本地不存储任何卡片正文。
- 一事一卡：一条 memo 一个念头/摘录/观点/事实，简短独立。
- 纯标签聚合、不建索引卡：组织只靠 `#标签` 层级（多级 `/` 细分），不建索引卡/MOC/母题目录；靠检索而非导航。
- 为回顾而写：首句说清这条讲什么/为什么记，让未来的自己扫标签+首句能捞起；不追求维基式三段，够清楚即可。

## 卡片格式（写云端的 memo 正文）

首行 `#标签/细分` 单独成段，空一行接正文。骨架：

```
#标签/细分

一句话核心结论：是什么/最想记住的点——一眼定位

要点：
- 要点一（为什么/依据）
- 要点二
- 可选：边界/反例——不是什么/何时失效

来源: https://真实来源（资料卡保留）
```

- 结论先行：正文首句为核心结论，一眼定位。
- **不设字数上限**：长度由内容定，压到够清楚即可、不注水。
- flomo 富文本边界（实测）：支持加粗 `**文字**`、高亮 `<mark>`、下划线 `<u>`、无序/有序列表（两级缩进两空格）、空行分段；不渲染标题/引用/代码块/链接/表格/图片，只作纯文本。外部链接保留为纯文本行（flomo 会渲染成可点链接，属正常）。
- 公式纯文本/Unicode（x²、√2、∑、μ、→），不写 LaTeX 美元符。中文为主，术语留英文；英文专名不硬译（Agent Harness、MCP、Skill）。
- 成组数字用列表分行（≥3 个并列数值逐行，列清指标/数值/变化）。

## 卡型

- 事实卡：记"是什么"——事实/机制/案例。
- 概念卡：记可复用概念的定义与机制。
- 框架卡/方法论卡：记"怎么分析"，标签常含 方法/方法论。
- 未竟思路卡：未解决、值得未来拾起的开放线索；首行含 `#未竟/主题`，正文=定界+已知+下一步想弄清。
- 应用回环卡：把某卡方法用到真实场景后发生了什么；正文=引用的卡+场景+结果+校准。
- 卡间只用单向链接，禁止双向回链（防成环）；跨主题靠检索。

## 标签规则

- 首行即标签段：多个 `#标签` 空格分隔；**每个都必须带 `#`**，裸词（如 `协调博弈` 不带 #）flomo 不识别为标签，只当正文。
- **子标签必须带主标签前缀**：写成 `#思想/协调博弈`，不能裸写 `#协调博弈`——裸写会建出独立顶层标签，破坏层级。flomo 实测 `#主/子` 正确解析为子标签。
- 首个为主标签（领域/主题），细分往后。
- 顶层禁止泛指词头：不用 `#概念/`、`#方法/`、`#主题/` 这类无信息量词头。
- 新顶层命名纪律（防同义裂变）：新建主标签前先核近义顶层是否已存在且可收纳——能归入既有绝不新建。高频同义对照（择一不重复建）：量子/=物理/=科技/（量子专属应用与基础物理分归 量子/与 物理/，技术产业通论归 科技/）；会计/=金融/（是否记账工具划界）；投资/=金融/（单标的估值归 投资/，市场/货币通论归 金融/）。确需新建登记进下方词表。
- 特殊卡型顶层：`#未竟/主题`、`#回环`——卡型分类标签，非泛指词头。
- 禁 emoji/特殊字符（`#😁`、`#读书&学习` 不可检索）；英文词用下划线连接（`#Apple_seed`）。
- 新建主标签、重命名/合并标签（tag_rename 全库同步）是需授权操作，先问用户。

## flomo 对接（本环境实测）

- flomo 提供 streamable-http MCP 端点 https://flomoapp.com/mcp，Bearer 鉴权（token 在 .mcp.json）。本环境无 MCP 面板，.mcp.json 不被加载，MCP 框架直连走不通。
- 实测可用 curl 直连：initialize（从响应头 Mcp-Session-Id 拿会话）→ notifications/initialized → tools/call（带会话头）；SSE 结果在 data 行的 result。写 memo 前先 get_format_guide 确认格式。
- 工具与参数见 flomo_client.py（实测透传 JSON，无额外封装）；差异项：memo_create(content；format 可选字符串 markdown/html，勿传布尔、省略即纯文本)、memo_update(id/content；format 可选同 memo_create)、tag_rename(old_tag/new_tag/max_memos)；依赖 flomo Max 会员。
- 卡间链接边界：结构化卡片链接 linked_memos 仅 memo_create 可设（memo_update 拒绝该字段）；正文 `((memo_id))` 语法经 MCP 写入不被解析为卡片链接。给已有卡补结构化链接只两条路——删旧建新（memo_create 带 linked_memos）或在 flomo App 手动加；勿用 memo_update 试探、勿留纯文本 id 引用。

## 记录流程（每次经 MCP 写云端）

1. **抓取（只读）**：网页 webfetch；GitHub 优先 raw + websearch 补 stars；arXiv 取标题作者摘要；清单/SPA 站 curl -L -A "Mozilla/5.0" 抓内嵌；403/超时 websearch 多源交叉兜底。同名对象先按域名/作者/用途消歧，来源行写确定对象。含音视频口播先判断动作类别并征求同意。SPA/动态站 curl 只拿到骨架时（无标题、正文为空、仅 __next_f 流式块），不得凭域名臆测内容；须从页面内联资源/外链（如唯一绝对 URL、GitHub 仓库、官方站）追到真实内容源并核验，来源行写真实核验路径而非表面域名（例：yami.yunfeihe.com 实为 DEEIX AI 产品页，写 deeix.com 与 github 仓库）。
2. **提炼**：滤营销话术，留事实/数据/因果链；不编造，未抓细节标（待核实）。值得未来拾起的开放思考记为未竟思路卡。
3. **定标签**：先 tag_tree 采云端完整标签树（每次写卡前现采，不复用同会话早前结果）；命中既有簇；新建顶层先问用户、用 memo_search 用 tag 参数核对该领域无近邻卡、不与既有同义。
4. **查重（阻塞式，写云前必做并显式报告）**：memo_search 按关键词/标签/时间扫云端，命中即通读判实质重复；双保险——关键词检索 + 用 tag 参数或 tag_tree 按标签维度再查一次覆盖漏判。注意：云端 `memo_search --tag` 对主标签维度常返回 0 命中（即使存在该细分卡），不可据此判"无近邻"；主标签检索空时须退回关键词检索 + 用 tag_tree 列出该领域所有细分卡逐条比对，避免漏查重。无命中→新建；完全重复→改指向原 memo；部分重叠→更新原 memo（计第 7 步）。回复须写明结论，不得用"已查重"敷衍。
5. **写作**：按卡片格式写成 1 条；可用 memo_recommended/memo_search 调旧记录衔接。
6. **写云前格式自检（阻塞式，不靠写完拉回纠错）**：调 `python scripts/validate_memo.py --content "..."`（或 `--create 请求json`）跑脚本，须 EXIT=0（0 ERR）才许写云；脚本覆盖 ①标签段首行/每个带#/子标签带主前缀（裸#子报 ERR）②标签段后空行 ③flomo 不支持的 MD 语法 ④来源行合法 URL（兼容 flomo 渲染后的 [text](url)）⑤占位/生造。WARN 不阻塞但须人工确认。任一项 ERR 先改再写，禁止把云端当草稿反复 memo_update。
7. **复盘建议（收口必做，两条缺一不可，每条极简给落点+执行+状态）**：
   - 常规：用 memo_search/memo_recommended 找相关 memo，判是否更新/合并/删除/升级框架卡（复盘主责在 memo 网络，不在配置文件）。无操作项说"本轮无 memo 需更新"。
   - 创新：当下可执行的增值动作——优先给 memo 层面建议，其次才是 SKILL 加规则；无创新说"本轮无强创新点"，不用触发条件式凑数。复盘提 SKILL 改动须是反复踩坑的共性规则，单次偶发不值得进 SKILL（避免膨胀）。
   - 落地状态标注：有 commit 附 hash；无需改文件标"已落地（无需改文件）"；未拍板标"待你决定"。禁止声明已落地而实际未执行。
8. **更新云端 memo（常驻末步，需授权）**：查重判部分重叠、你点名改、或需合并标签时执行。先 memo_search+memo_batch_get 定位通读，展示改动前后，同意调 memo_update（保持首行标签段）。无需求明示"本轮无 memo 需更新"。memo_delete 不提供，由用户在 App 手动删（先展示拟删项征得同意，删完复盘明示含 memo id）。

## 正文防标签误识别

flomo 扫全文 `#xxx` / `/xxx` 当标签，非仅首行。写前通读草案，按下表预判改写，比写后 memo_update 补救省一轮；已误识别用 memo_update 覆盖正文去掉触发符即可，脏标签无引用即消失：

| 触发源 | 示例 | 改写 |
|---|---|---|
| issue/编号/PR/章节前的 # | `#8435` | 去 #（"issue 8435"） |
| 档位/排名里的 #数字 | `≤#150` `#1 档` | 中文（"第150位""榜首"） |
| 技术名前的 / | `C#/.NET` `/API` | 空格或"与/及"连接 |

## 提炼模板索引（按内容类型选用）

- 清单型：首句总括→按维度分组一行一要点→尾行来源；时效钩子只作背景。
- 技术首秀型：规模里程碑→物理瓶颈机制→商业化路径→路线对照；时效事件只作证据锚点。
- 雇佣式攻击型：攻击本质→运作机制→典型案例→专家定性→防御路径；主语落可复用攻击模式。
