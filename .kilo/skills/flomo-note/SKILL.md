flomo 卡片笔记（云端）

本文件是执行细则的唯一来源；项目总则见 AGENTS.md，两者不重复记录。
体系：flomo 极简卡片 + 标签聚合，笔记只存云端 flomo，本地不落任何卡片正文。本目录仅存放本技能、AGENTS.md、.mcp.json。

【执行铁律】（每次动手前先对照，违背即事故）

1. 只读/需授权先分类：webfetch、websearch、memo_search、tag_tree、memo_batch_get、memo_recommended、get_format_guide、get_tag_guide、memory_context、memory_user 可直接做；memo_create、memo_update、tag_rename、下载保存文件、本地重型工具必须先向用户展示内容并等明确同意，绝不静默写云端。
2. 写前必抓取：凡带来源 URL 的 memo，写入前该 URL 必须已真实抓取成功并基于实际内容写作；未抓取、抓取失败、凭链接猜内容一律禁止写云。纯想法无来源 memo 不受此限，但不得虚构来源。生造 URL 视同编造来源。
3. 调 flomo 脚本一律走 flomo_client.py --file 从文件读 JSON 参数（PowerShell 中文环境会把内联引号转全角导致解析失败），绝不用内联 JSON。
4. 写云前必须先查重并显式报告结论（命中什么/无重复），不得用"已查重"三字敷衍。
5. 复盘建议必须一次同时输出两条（常规+创新），成对出现；每条极简一句，标注落地状态（已落地/待你决定）。
6. 不外传、不评估卡间关系：卡的组织只靠标签承载，卡间关系仅在实际查重/合并时按需判断，不作为复盘建议或观察项主动提出。

定位与理念

- 笔记在云端：每张卡片就是一条 flomo memo，经 MCP 的 memo_create 直接写入你的 flomo 账号；本地不存储、不落盘任何卡片正文。
- 一事一卡：一条 memo 一个念头/摘录/观点/事实，简短独立，不建本地文件夹。
- 纯标签聚合、不建索引卡：组织只靠 #标签 层级（多级 / 细分），不建立任何索引卡 / MOC / 母题目录；顶层用领域或主题名，靠标签检索而非索引导航。此为项目惯例，不因卡量增长改变。
- 标签即结构：卡片靠 #标签 聚合成簇，可层层细分（#AI/AgentHarness、#经济/统一大市场）；层级以云端 flomo 标签树为准。
- 为回顾而写：首句说清"这条讲什么/为什么记它"，让未来的自己扫一眼标签和首句就能捞起。不追求维基式"定义+解释"三段式，够清楚即可。

卡片格式（写到云端的 memo 正文）

标签放正文开头第一行单独成段，空一行接正文，flomo 自动把首行 #标签 识别为标签。骨架：

#标签/细分

一句话核心结论：是什么/最想记住的点——一眼定位

要点：
- 要点一（为什么/依据）
- 要点二
- 可选：边界/反例——"不是什么/何时会失效"

来源: https://真实来源（资料卡保留）

flomo 富文本边界（官方 get_format_guide 实测）：
- 支持渲染：加粗 **文字**、高亮 <mark>文字</mark>、下划线 <u>文字</u>、无序列表 - 项目（两级缩进两空格）、有序列表 1. 项目；段落用空行分隔。
- 不渲染：标题、引用、代码块、链接、表格、图片等其他语法，只作纯文本；外部来源链接保留为纯文本行。
- 正文只用原生格式，避免写不生效的 Markdown 排版符号。

卡型总览（完整卡片类型）：
- 事实卡：记"是什么"——主题的事实、机制、案例（稳态知识）。
- 概念卡：记一个可复用概念的定义与机制（稳态知识，如 Data as Git、词元估值）。
- 框架卡/方法论卡：记"怎么分析"——抽象出的可复用分析框架（稳态知识，标签常含 方法/方法论）。
- 未竟思路卡：记"尚未解决、未来值得回来处理"的开放思考线索（进行时，见写作规范）。
- 应用回环卡：记"把某卡方法/概念实际用到真实场景后，发生了什么、结论成不成立"（反馈闭环，见写作规范）。
- 卡与卡可用单向链接关联（框架卡回链事实卡、应用回环卡回链原方法卡等）：只用单链，禁止双向互相回链——被引用的卡不反向回指引用它的卡（避免双链成环）；纯标签聚合下不建索引卡，跨主题归拢靠检索。

标签规则

- 首行即标签段：一个或多个 #标签，空格分隔（多级用 /）。首个为主标签（领域/主题），细分往后，顶层直接用领域或主题名。
- 顶层禁止泛指词：不用 #概念/、#方法/、#主题/ 这类无信息量词头（会占用词头、把所有卡挤进笼统口袋）。"用概念分类"指归属到知识点本身，不是套一层"概念/方法"标签。
- 特殊卡型顶层约定：#未竟/主题（未竟思路卡）、#回环（应用回环卡）——这是卡型自身的分类标签，不属于泛指词头。
- 禁 emoji/特殊字符：如 #😁、#读书&学习 会导致无法检索，禁用。英文词用下划线连接（#Apple_seed）。
- 新建主标签、重命名/合并标签（tag_rename 会全库同步改名）是需授权操作，先问用户再执行。

flomo 对接（本环境实测可用的连接方式）

- flomo 提供 streamable-http 的 MCP 端点 https://flomoapp.com/mcp，Bearer 鉴权（token 在项目 .mcp.json）。本环境 TRAE 无 MCP 面板，.mcp.json 不被加载，MCP 框架直连走不通。
- 实测可用：curl 直连端点，先 MCP 握手拿会话，再 tools/call 调工具。步骤：initialize（从响应头 Mcp-Session-Id 拿会话）→ notifications/initialized → tools/call（body 含 name、arguments，带会话头）；SSE 结果在 data 行的 result。写 memo 前先 get_format_guide 确认最新格式。
- 工具与关键参数（实测）：memo_search（keywords 多词空格=AND、tag、start_date、end_date、from、has_tag、limit≤50）；tag_tree（prefix/depth/limit）、tag_search（keywords/limit）；memo_batch_get（id，≤10）、memo_recommended（id/limit/no_same_tag）；memo_create（content/format）、memo_update（id/content/format/local_updated_at）、tag_rename（old_tag/new_tag/max_memos）；memory_context / memory_user（无参）；get_format_guide / get_tag_guide（无参）。依赖 flomo Max 会员。

记录流程（每次经 MCP 写云端）

1. 抓取（只读）：网页 webfetch；GitHub 优先 raw.githubusercontent.com/用户/仓库/main/README.md + websearch 补 stars；arXiv 取标题作者摘要；清单站与 SPA 站 curl.exe -L -A "Mozilla/5.0" 抓内嵌；403 或超时则 websearch 多源交叉兜底。内容含音/视频口播或需转写时先判断动作类别并征求同意。
2. 提炼：滤营销话术，留事实/数据/因果链，压成十几到几百字；不编造，未抓细节标"（待核实）"。本轮若产生"还想弄/没想清/待验证"且值得未来拾起的念头，记为未竟思路卡（见写作规范）。
3. 定标签：先 flomo.tag_tree 采云端完整标签树（不能用本地文件代偿），命中既有簇；顶层新主标签先问用户避免碎片化，新建前先 memo_search 用 tag 参数核对该领域确无近邻卡、不与既有顶层同义。
4. 查重（阻塞式，写云前必须完成并显式报告）：memo_search 按关键词/标签/时间（含语义）扫云端，命中候选即通读判实质重复。双保险：关键词检索 + 用 tag 参数或 tag_tree 按标签维度再查一次，覆盖"关键词没撞上但同标签已存在"的漏判。判定：无命中→新建；完全重复→不再写、改指向原 memo；部分重叠→更新原 memo 正文（计入第 8 步）；清单类一行提及→可单独建并从原处回链。回复必须写明结论（"查重：云端命中 X 篇（列名）或无重复"），不得用"已查重"三字敷衍。
5. 写作：按"卡片格式"+"写作规范"写成 1 条（一事一卡）；可用 memo_recommended、memo_search 调旧记录衔接上下文。
6. 写云（新建，需授权）：把最终正文+首行标签段完整展示给用户并说明将写入你的 flomo 账号，经同意后调 memo_create（内容与展示一致）。写前硬校验：带来源的 memo 其来源必须已真实抓取成功并基于实际内容写作（否则禁止写云、先补抓取）；无来源纯想法不受限但不得虚构来源。除非已约定"写卡直接落云"，否则必须停下等同意；本次不写云须明示。若查重判"部分重叠"，本步不新建，走第 8 步统一更新。新建成功即完成，无索引卡（本项目不建索引卡）。
7. 复盘建议（收口后必做）：必须一次同时输出两条——常规一条+创新一条，缺一不可、成对出现；两条都无可写时各自明说"无"但要对齐出现。每条极简一句，给具体落点+触发理由+执行方式并征询是否落地，标注落地状态（已做完标"已落地"，未拍板标"待你决定"）。规则：
   - 常规建议：从 SKILL / AGENTS / 既有 memo / 标签体系 / 脚本工具 / 记忆惯例中找最值得的一条可执行项（含对既有 memo/标签的更新、合并、删除——复盘扫一遍本轮查重/写作/提炼是否实际催生了对某条既有卡或某标签的更新/合并/删除需求，有则提出，落点指到具体那张卡/标签；这是按本轮具体处理按需触发，不是主动评估卡间关系）。
   - 创新建议：有主动增值方向（新卡型/新提炼模板/新流程机制）则提一条；没有就明确说"本轮无强创新点"，宁缺毋滥。
   - 写卡落点按五种卡型逐项核对：若考虑"是否再写一张卡"，必须从五种卡型（事实/概念/框架/未竟思路/应用回环）逐一核对，指明写哪种、触发条件；不用含糊的"写个方法卡"一带而过；确无可写或某卡型本轮已写过则如实注明。
   - 对 SKILL 的改动遵循"更新/合并/删除"三态：更新=改表意不换原意或加新行；合并=两条重复/过近并为一条；删除=明确过时/被取代可判定时删行（须给理由）。先说明改哪一行、哪种、为何，获同意后落地；不改则明示"本轮 SKILL 不改动"。
8. 更新云端 memo（常驻最后一步，需授权）：当查重判"部分重叠"、或你点名修改某条（改正文/补标签/改来源/去重）、或需合并整理标签时执行。先用 memo_search + memo_batch_get 定位并通读原 memo；明确要改的那一点；展示改动前后；获同意后调 memo_update（保持首行标签段）。本轮无更新需求则明示"本轮无 memo 需更新"，不必硬走。memo_update 是写操作需授权，绝不静默改云端。删除 memo（纠错/去重出口）：当查重判"完全重复且新建错误"、或你点名删某条（误写/作废/被正确版取代）时走此动作——flomo MCP 不提供 memo_delete 工具，故经你确认后由你在 flomo App 手动删除；先把拟删 memo 的序号、标签与正文展示给你并征得同意，删完在复盘里明示结果（含 memo id 与内容确认）。

写作规范

- 结论先行：首句是卡片一句核心结论。
- 不设字数上限：正文长度由内容决定，够清楚即可，不强制拆卡。
- 公式与数学：flomo 刻意不支持 LaTeX，不写美元定界符，数学公式一律纯文本/Unicode 表达（x²、√2、a/b、∑、μ、→）。中文为主，术语保留英文。
- 英文专名不硬译：直接用原文专名（Agent Harness、MCP、Skill）。
- 成组数字用列表分行（flomo 无表格）：≥3 个并列数值指标（带同比/环比/占比/金额等口径）用无序/有序列表逐行拆开，如 "- 营收 12.5 亿，+8%"，列清指标/数值/变化。
- 时序新闻去热（高时效必做）：来源是"本周发布/某模型上线"类高时效内容时，memo 主语落在可复用的机制/概念/规格而非事件时间点，留一个反时效持久锚点（归入既有主标签或抽象成可复用模式）；无法抽象的时效快照判不值得独立成 memo，并入上位或舍弃。
- 捕捉持久线索（去热强化）：遇"XX 新品发布"类新闻，优先捕捉厂商的命名/版本/代号体系这类低时效持久线索（如 Anthropic 用文学体裁命名模型），比追单品时效快照更值得成卡，未来可反复复用。
- 复杂系统瓶颈口诀化：遇复杂系统/产业瓶颈类内容，主动把核心障碍压缩成"三X一Y"式口诀——三个并列短板（低/贵/高/缺）+ 一个最痛点（高/缺/难/慢），如数据"三低一高"、算力"三贵一缺"。口语便于记忆、沟通、复用；提炼后可选拆框架卡。
- 事实-框架双卡模板（主题卡可选增强）：遇主题/概念卡，主动判断是否值得同时提炼一张可复用的方法论/框架卡——事实卡记"是什么"，框架卡记"怎么分析"（可复用分析框架，如算力组织三模式、实证-规范-实践三分法）。两卡双链关联，标签同顶层不同细分（如 经济/学科史 + 经济/方法论）。判断标准：该主题的分析框架能否迁移到其他场景；能则值得拆，不能则只写事实卡。
- 未竟思路卡（记进行时的思考线索）：专门记一个"尚未解决、未来值得回来处理"的开放思考线索，是体系里唯一"记进行时"的卡型。写卡时机：出现"我还想继续弄/没想清/待验证"且值得未来拾起时。正文=一句话定界这条待办探究 + 目前已知（推到哪）+ 下一步想弄清什么/触发条件；首行含 #未竟/主题。一事一卡，不可把多条装进一张清单卡。生命周期：遇进展回链刷新——推进则更新、解决则记结论并关闭、放弃则记原因并关闭，关闭后不再累积。判据：写前自问"这条是否要我未来还回来"，不用就并入内容卡。与事实/概念/方法卡区分：那些记"已完成的知识"（稳态），未竟思路记"未完成的想法进度"（进行时），解决后结论可长成独立知识卡。纯标签聚合下无索引，靠 #未竟 + 细分检索。
- 应用回环卡（记知识被用起来后的校验）：记录"把某卡的方法/概念实际用到一个真实场景后，发生了什么、结论成不成立"，让笔记从"只进不校"变为能自我纠正。正文=引用的卡（纯文本链接/标签）+ 用到的真实场景 + 结果（验证成/发现不适用/哪里要校准）+ 对原方法的校准。写卡时机：实际调用某卡的方法/概念处理真实问题之后。与方法卡区别：方法卡存"怎么分析"，回环卡存"这次应用的结果证据"；与事实卡区别：事实卡记现象事实，回环卡记"方法×场景"的验证证据。生命周期：可作原方法卡的反馈校准（回链补充结论），也可独立留存。纯标签聚合下无索引，靠 #回环 + 细分检索。
