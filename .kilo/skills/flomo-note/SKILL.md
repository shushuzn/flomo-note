# flomo 卡片笔记

> 本文件是**执行细则的唯一来源**；项目总则见 `AGENTS.md`，两者不重复记录。
> 体系：flomo 极简卡片 + 标签聚合。核心是「一事一卡、轻量简短、靠标签找、为浮墨式回顾而写」。不用文件夹树、不用 `[[双链]]`、不用 Obsidian CLI。

## 定位与理念

- **一事一卡**：一张卡片一个念头/一条摘录/一个观点/一条事实，短小而独立（约 40–300 字）。卡片是唯一知识载体，共享一个扁平库，不建深层子目录。
- **标签即结构**：卡片靠 `#标签` 聚合成簇，可层层细分（`#ai/agent` `#经济/税制`）。需要时用一个主标签下的**索引卡**串起该簇卡片，作为该标签的目录。
- **为浮墨式回顾而写**：一句话说清"这条讲什么 / 为什么记它"，让未来的自己扫一眼标签和首句就能捞起来。不追求维基式的"定义+解释"三段式，够清楚即可。
- **无文件夹、无 Obsidian 依赖**：卡片直接平铺在库根；检索用 `rg "#标签"` / 关键词，不用 Obsidian CLI。

## 红线与许可

**防错红线：**
- **成品一律入主库，禁用 `.workbuddy/` 存成品**：成品（代码、HTML 可视化、图表、报告等交付物）必须放主库对应位置（如 `out/xxx.html`）并纳入 git。`.workbuddy/` 只放中间态工作数据（临时扫描、草稿、缓存），默认忽略、不对用户交付；拿不准按成品入主库并询问。
- **来源 URL 必须真实可核、严禁生造**：`source` 与 `## 来源` 里的 URL 必须是确实抓取/核验过的链接。无真实来源时：`source: ""`，`## 来源` 写「（非网络抓取，来源为 X）+ 本库文件路径」。生造 URL 视同编造来源。
- **外部事实先核验再下结论**：涉及"某物是否真实存在"的判定（模型/仓库/事件）先取证再表态；先前判断过头的直接明言更正并给证据。

**操作许可边界（抓取/转写前先分类）：**
- **只读 / 轻量（可直接做）**：webfetch、websearch、读取官方只读接口（标题/简介/字幕列表/评论等 GET）、读本地文件、查重、标签扫描。
- **需先征得用户明确允许（不得按流程惯性擅自动手）**：① 下载/保存任何文件到本地（含音视频流）；② 调用需下载或消耗资源的本地重型工具/模型（ASR 转写、图像生成/编辑、TTS、OCR、本地大模型等，常伴随下载数 GB 模型）；③ 对外部服务发消息/推送/批量写；④ 任何用户此前明确反对或未同意过的路径。
- 每步动作开头先**自标类别**（"只读"或"需授权"），对需授权动作说明后果并**停下等待同意**；拿不准按需授权处理。

## 卡片格式与模板

卡片为扁平 `.md` 文件，直接放库根（不建子文件夹）。文件名 = 卡片短标题或时间戳，避 `/\:*?"<>|`，冲突名尾加 `-2`。

### 卡片 = 第一行单独成段放标签 + 正文（全场唯一格式，不再有 YAML 壳）

```markdown
#概念/AgentHarness #AI

正文：自己话、一事一卡，多长多短都行。
```

标签按 flomo 官方规则，**第一行单独成段**，空一行后再接正文：
- **第一条即标签段**：一个或多个 `#标签`，空格分隔（如 `#概念/AgentHarness #AI`）。
- **格式**：`#标签`；多级用 `/`：`#标签/子标签/孙标签`。
- **禁 emoji / 特殊字符**：`#😁开心`、`#读书&学习` 会导致无法检索，禁用。
- **英文词用 `_` 连接**：如 `#Apple_seed`。
- 首个标签为主标签（最宽聚合单元），细分往后。

**其余规则：**
- 每条必带 ≥1 个 `#标签`，全部集中在第一行标签段。
- 抓取了外部资料要留出处的卡，文末加一行 `来源: url`；原创/随手记不加。
- 摘录关键句用引用块注明出处，不整段抄原文（存"提炼后的自己话"）。

## 正文结构（防乱写，默认骨架）

正文用统一骨架，避免随手乱写。核心是**结论先行、要点精炼、来源殿后**；随手卡可略去要点段，但首句"一句话结论"不可省：

```markdown
一句话核心结论（是什么 / 最想记住的点）——一眼定位

- 要点一（为什么 / 依据，≤3 条）
- 要点二
- （可选）边界 / 反例——"不是什么 / 何时会失效"

来源: url   ← 资料卡才需要，放正文最后
```

规则：
1. **结论先行**：首句即卡片核心结论，读完一眼知道重点，不铺背景。
2. **要点 ≤3 条**：支撑/依据用自己的话；到第 4 条就该拆成下一张卡（原子化）。
3. **边界可选但防误解**：遇到易混/易失效点，加一条"注意 / 反例"。
4. **来源殿后**：资料卡把 `来源: url` 固定放正文最后一行；原创 / 随手记无来源行。

## 流程（7 步）

1. **抓取**（只读，按源分流）——网页 `webfetch` / GitHub 优先 `raw.githubusercontent.com/<user>/<repo>/main/README.md`（网页 403 时）+`websearch` 补 stars / arXiv 取标题作者摘要 / 清单站与 SPA 站点 `curl.exe -L -A "Mozilla/5.0"` 抓内嵌数据 / 头条等反爬站改移动端 UA 试 `m.toutiao.com`；403/超时则 `websearch` 多源交叉兜底。**涉及内容在音/视频口播或需转写时，先读「红线与许可」判断动作类别并征求同意。**
2. **提炼**：滤营销话术，留事实/数据/因果链，压成十几到几百字的卡片话；不编造，未抓细节标"（待核实）"。
3. **定标签**：先采样该库已有标签（`rg -o "#[^ \t\n：]+" -g "*.md" . | sort | uniq -c | sort -rn`），优先命中既有簇；顶层新主标签先问用户，避免标签碎片化。
4. **查重（阻塞式，写作前必须完成并显式报告）**：
   - 用 `rg -l "#主标签|标题关键词" -g "*.md" .` 扫库，命中候选即通读判断实质重复。
   - **判定处理**：无命中→新建；完全重复→来源块并列追加链接；部分重叠→合并进现有卡片（更新其正文与来源）；清单类一行提及=部分重叠→新建专条并在清单处回链。
   - **回复必须明确写出查重结论**（如"查重：命中 X 篇（列名）或无重复"），不得用"已查重"三字敷衍。
5. **写作**：直接写成 1–3 张卡片（一事一卡，来源直链 URL）。
6. **标签闭环**：确认新卡的首标签命中既有主标签簇（碎片化时并入既有簇或归出新簇，先问用户）；某主标签下卡片达约 6 条时，可顺手在该簇建一张同名概览 `.md`（纯文本，列各卡文件名+一句话），非强制。
7. **自检→收口→提交**：
   - **收口机制（每轮必做，防"只做部分"）**：本轮结束前回看本轮任务完整范围，确认无遗漏再提交；确有跨轮未完成事项必须显式告知用户，不得静默丢弃。
   - 跑 `powershell -ExecutionPolicy Bypass -File .kilo/skills/flomo-note/check.ps1 -Strict`，修掉错误级缺陷；再 `git add/commit/push`（见「提交与同步」）。
8. **复盘改进建议（收口后必做）**：结合当轮所建/所改卡片，提出 **≥1 条对当前项目（本库标签体系、卡片规范、话题方向）的可执行改进建议**，随收口一并交用户。须具体可落地（如"新增某顶层主标签""把零散卡片并入既有簇""某主标签已厚可建概览卡"），并说明由该卡片触发的理由；不得空泛。

## 写作规范

- 文件名 = 卡片一句话标题（如 `AI Agent 的分层架构.md`、`分税制的三次修正.md`）。
- 结论先行：正文一句直接成片；`#标签/子标签` 单独放第一行成段，空一行接正文。
- 简短优先：目标 40–300 字；超过约 400 字就该拆成多张卡片，而非挤进一张。
- 公式用 LaTeX：行内 `$…$`、块级 `$$…$$`；中文为主，术语保留英文。
- **英文专名不硬译作标题**：标题/文件名直接用原文专有名词（`Agent Harness`、`MCP`、`Skill`），不硬译成中文打头；中文可括注于主名后，不得取代主名。
- **成组数字必须用表格**：≥3 个并列数值指标（尤其带同比/环比/占比/面积/金额等口径）一律用 Markdown 表格，按口径分组，列清指标/数值/变化/说明。
- 文件必须无 BOM 的 UTF-8：用 write 工具或 Python 写；PowerShell `Set-Content -Encoding UTF8` 会产生 BOM，禁用。
- **时序新闻去热规则（高时效内容必做）**：来源是"本周发布/某模型上线/某事件"这类高时效内容时，卡片主语落在**可复用的机制/概念/规格**，而非事件的时间点；并配一个**反时效的持久锚点**（归入既有主标签，或抽象出可复用模式）。无法抽象出持久锚点的高时效快照，判不值得独立成卡，并进上位卡片或舍弃。

## 建标签规范

- 标签层级用 `/`：`#ai/agent`、`#经济/税制`。首段是主标签（宽），细分体现差异。
- **不强制建目录**：不建目录卡、不用双链。标签本身即检索索引，零星卡片没有概览是正常状态，宁缺毋滥。
- **同类速查约定（簇变厚必做）**：某主标签下出现 **≥6 条能力相似**卡片时，在该主标签建的概览卡顶部加「同类速查」对比（固定维度：主体/输入/产出/协作模式），把差异讲清，避免靠描述瞎猜。

## 合并与更新

- **部分重叠卡片**：把新来源实质内容（数据、事实）正常并入正文，来源块**并列多条链接**（每条写媒体+作者，不写日期前缀、不加"更新："二字）。
- **"更新"字样禁令**（范围固定，不得自行扩大或缩小）：
  - **禁止**：卡片里"更新：YYYY-MM-DD"修订日志式时间标注，以及"单独的带日期来源行"（如 `- 更新：2026-08-20 https://...`）。
  - **允许**：技术术语与正常叙述里的"更新"照常写、不替换——如「梯度更新」「热更新」「城市更新」「价格更新」「数据记录更新」「知识库更新」。这些不是修订标注，禁令不覆盖。
  - **严禁**因用户否定"更新"写法而删掉已并入的正文内容/数据——"不要更新二字"只指去掉修订日志格式，不指丢弃内容。
  - 动笔改"更新"前先分类：是"更新：日期"格式（才处理）还是术语/叙述（一律不动）。拿不准保留原词，不许猜删。
- 需要时可用 `git mv` 给卡片改名保历史；新主标签（新宽标签）先询问用户再建。

## 自检与质检（提交前必跑）

- **质量标尺（flomo 式）**：✅ 一事一卡、简短得体、用自己的话、标签格式合法（`#标签/子标签`、无禁字符、多条用空格）、有外部来源必留出处、英文专名不硬译；❌ 整段摘抄无提炼、一张卡塞多件事、标签用禁字符(emoji/&)/数量过多、超长不拆分、成组数字散文罗列、生造来源 URL、BOM 导致正文解析失败。
- 脚本：`powershell -ExecutionPolicy Bypass -File .kilo/skills/flomo-note/check.ps1 -Strict`（引擎 `audit.py`；只读不写；校验 标签格式/出处/文件名/BOM/字数，Strict 遇错误级缺陷退出码 1）。
- **验证已落盘**：新建卡文件在库根可 `Read`。
- 提交前用 `git status` 确认只加了目标卡片，没误提交 `.workbuddy/` 等中间数据。

## 提交与同步

- 本库（`d:\OpenClaw\flomo-note`）需先 `git init` 一次并建 `.gitignore`（忽略 `.kilo/`、`.workbuddy/`、`node_modules/` 等）；之后沿用：PowerShell 用 `;` 串联，不用 `&&`。
- `git add <卡片>`；`git commit -m "Add <卡片名> card: <摘要>"`；`git push`（超时 90000ms）。push 属外部操作，按「红线与许可」视情况征求同意。
- 代理 `127.0.0.1:7897` LISTENING 才设 `http.proxy/https.proxy`，否则直连；`Connection was reset` 切代理重试。

## 标签检索参考

flomo 库无文件夹，全靠标签与检索捞卡：

| 目的 | 方式 |
|------|------|
| 按主标签列卡 | `rg "#主题" -l -g "*.md" .` |
| 按细分标签 | `rg "#主题/子主题" -g "*.md" .` |
| 关键词检索 | `rg "关键词" -g "*.md" .` |
| 采样全库标签 | `rg -o "#[^ \t\n：]+" -g "*.md" . | sort | uniq -c | sort -rn` |
| 全库卡数 | `(Get-ChildItem -Filter *.md -File).Count`（排除 AGENTS/README） |
