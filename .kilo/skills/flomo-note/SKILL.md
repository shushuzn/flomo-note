flomo 卡片笔记（云端）

本文件是执行细则的唯一来源；项目总则见 AGENTS.md，两者不重复记录。
体系：flomo 极简卡片 + 标签聚合，笔记只存云端 flomo，本地不落任何卡片正文。本目录仅存放技能文档与 MCP 配置。

定位与理念

- 笔记在云端：每张卡片就是一条 flomo memo，通过 flomo MCP 的 memo_create 直接写入你的 flomo 账号；本地（d:\OpenClaw\flomo-note）不存储、不落盘任何卡片正文。
- 一事一卡：一条 memo 一个念头/一条摘录/一个观点/一条事实，简短独立。不建本地文件夹。
- 纯标签聚合、不建索引卡：笔记组织只靠 #标签 层级（多级 / 细分），不建立任何索引卡 / MOC / 母题目录；顶层直接用领域或主题名，需要找某主题时靠标签检索，而非额外的索引卡导航。此定位为项目惯例，不因卡量增长而改变。
- 标签即结构：卡片靠 #标签 聚合成簇，可层层细分（#AI/AgentHarness、#经济/税制）。标签层级以云端 flomo 的标签树为准。
- 为浮墨式回顾而写：一句话说清"这条讲什么 / 为什么记它"，让未来的自己扫一眼标签和首句就能捞起来。不追求维基式"定义+解释"三段式，够清楚即可。
- 本地只留工具：本目录 = 本技能 + AGENTS.md(总则) + .mcp.json(含 token 的 MCP 配置)；git 只追踪这些技能/配置文档，不追踪任何卡片内容（没有也不应有）。

红线与许可

防错红线：
- 不外传你的笔记内容：写入云端前把 memo 正文展示给用户确认，不得静默写云端。
- 来源 URL 必须真实可核、严禁生造：memo 里出现的链接必须是确实抓取/核验过的。无真实来源时写"（非网络抓取，来源为 X）"，生造 URL 视同编造来源。
- 写云前必须已实际抓取过来源：凡带来源 URL 的 memo，写入前该 URL 必须已 WebFetch/抓取成功并基于真实内容写作；未抓取、抓取失败或凭链接猜测内容，一律禁止写云（防止编造卡片）。纯想法/无来源 memo 不受此限，但不得虚构来源。
- 外部事实先核验再下结论：涉及"某物是否真实存在"的判定（模型/仓库/事件）先取证再表态。

操作许可边界（抓取/写云前先分类）：
- 只读 / 轻量（可直接做）：webfetch、websearch、读取官方只读接口、flomo.memo_search、flomo.tag_tree、flomo.memo_batch_get、flomo.memo_recommended、flomo.get_format_guide、flomo.get_tag_guide、flomo.memory_context、flomo.memory_user。
- 需先征得用户明确允许：① flomo.memo_create、flomo.memo_update、flomo.tag_rename（写/改云端数据，每次执行前说明将写入的内容并等同意）；② 下载/保存文件到本地；③ 调用需下载或消耗资源的本地重型工具；④ 任何用户此前明确反对的路径。
- 每步动作开头先自标类别（"只读"或"需授权"），对需授权动作说明后果并停下等待同意；拿不准按需授权处理。

flomo 对接（本环境实测可行的连接方式）

- flomo 提供 streamable-http 的 MCP 端点 https://flomoapp.com/mcp，用 Bearer 鉴权（token 由用户提供，记在项目 .mcp.json）。本环境 TRAE 无 MCP 面板，且 .mcp.json 不会被加载（run_mcp 报 server not found），MCP 框架直连走不通。
- 实测可用方式：用 curl 直连该端点，先 MCP 握手拿会话，再 tools/call 调工具。
- 调用步骤：
  1. initialize：curl.exe -s -X POST https://flomoapp.com/mcp -H "Content-Type: application/json" -H "Accept: application/json, text/event-stream" -H "Authorization: Bearer <token>" --data-binary "MCP initialize 请求 JSON"，从响应头 Mcp-Session-Id 拿会话 ID。
  2. notifications/initialized（带同一会话）。
  3. tools/call：body {method:tools/call, params:{name,arguments}}，带 Mcp-Session-Id 头；响应为 SSE，结果在 data 行的 result 里。
  4. 写 memo 前先调 get_format_guide 确认最新格式规范（含加粗/高亮/下划线/列表标签写法）。
- 工具与关键参数（本环境实测）：
  - memo_search（查重/检索）：keywords（检索词，多词空格分隔表示 AND，勿用 | 或相对时间词）、tag、start_date、end_date、from、has_tag、limit（最多 50）。
  - tag_tree（标签树）：prefix（前缀过滤）、depth、limit；tag_search（定位）：keywords、limit。
  - memo_batch_get（批读）：ids（数组或单 id，最多 10）；memo_recommended（联想）：id、limit、no_same_tag。
  - memo_create（写）：content（必填）、format；memo_update（改）：id（必填）、content、format、local_updated_at；tag_rename（改标签）：old_tag、new_tag（必填）、max_memos。
  - memory_context / memory_user（读记忆档案）：无参数。
  - get_format_guide / get_tag_guide：无参数；创建/整理前先调用确认规范。
  - 依赖 flomo Max 会员。

卡片格式（写到云端 memo 的格式）

云端 memo 的标签放在正文开头第一行单独成段，空一行接正文，flomo 自动把首行 #标签 识别为标签。

通用卡片骨架（写入云端的 memo 正文）：

#标签/细分

一句话核心结论：是什么 / 最想记住的点——一眼定位，不强求分段

要点：
- 要点一（为什么 / 依据）
- 要点二
- 可选：边界 / 反例——"不是什么 / 何时会失效"

来源: https://example.com（资料卡保留）

flomo 富文本边界（官方 get_format_guide 实测）：
- 支持并渲染：加粗 **文字**、高亮 <mark>文字</mark>、下划线 <u>文字</u>、无序列表 - 项目（两级嵌套用两空格缩进）、有序列表 1. 项目；段落用空行分隔。
- 不渲染：标题、引用、代码块、链接、表格、图片等其他语法（只作纯文本；外部来源链接按用户要求保留为纯文本行，不追求可点链接）。
- 正文按需用这些原生格式，避免写不生效的 Markdown 排版符号。

卡型总览（本项目确立的完整卡片类型）：
- 事实卡：记"是什么"——主题的事实、机制、案例（稳态知识）。
- 概念卡：记一个可复用概念的定义与机制（稳态知识，如 Data as Git、词元估值）。
- 框架卡 / 方法论卡：记"怎么分析"——抽象出的可复用分析框架（稳态知识，标签常含 方法/方法论）。
- 未竟思路卡：记一个"尚未解决、未来值得回来处理"的开放思考线索（进行时的想法，见写作规范）。
- 应用回环卡：记"把某张卡的方法/概念实际用到一个真实场景后，发生了什么、结论成不成立"（反馈闭环，见写作规范）。
- 卡与卡之间可用双链关联（框架卡回链事实卡、应用回环卡回链原方法卡等）；纯标签聚合下不建索引卡，跨主题归拢靠检索。

标签规则

- 第一行即标签段：一个或多个 #标签，空格分隔（多级用 /：#标签/子标签/孙标签）。
- 首个标签为主标签（领域/主题词），细分往后。顶层直接用领域或主题名。
- 顶层禁止泛指词：不用 #概念/、#方法/、#主题/ 这类无信息量词头——"用概念分类"指归属到知识点本身，不是套一层"概念/方法"标签（会占用词头、把所有卡挤进笼统口袋）。顶层直接用领域或主题名。
- 特殊卡型的顶层标签约定：#未竟/主题（未竟思路卡）、#回环（应用回环卡）——这两个是卡型自身的分类标签，不属于泛指词头。
- 禁 emoji / 特殊字符：#😁开心、#读书&学习 会导致无法检索，禁用。
- 英文词用下划线连接（如 #Apple_seed）。
- 新建主标签、重命名/合并标签（tag_rename 会全库同步改名）都是需授权操作，先问用户再执行。

记录流程（每次经 MCP 写云端）

1. 抓取（只读）——网页 webfetch；GitHub 优先 raw.githubusercontent.com/用户/仓库/main/README.md + websearch 补 stars；arXiv 取标题作者摘要；清单站与 SPA 站 curl.exe -L -A "Mozilla/5.0" 抓内嵌；403 或超时则 websearch 多源交叉兜底。涉及内容在音/视频口播或需转写时，先判断动作类别并征求同意。
2. 提炼：滤营销话术，留事实/数据/因果链，压成十几到几百字；不编造，未抓细节标"（待核实）"。本轮若产生"还想继续弄 / 没想清 / 待验证"的念头，且值得未来拾起，记为未竟思路卡（见写作规范）。
3. 定标签：先 flomo.tag_tree 采云端完整标签树（不能用本地文件代偿），命中既有簇；顶层新主标签先问用户，避免碎片化。新建顶层主标签前，先 memo_search 用 tag 参数（如 tag: 金融）核对该领域确无近邻卡，且新标签不与既有顶层同义，再行确认。
4. 查重（阻塞式，写云前必须完成并显式报告）：用 flomo.memo_search 按关键词/标签/时间（含语义）扫云端，命中候选即通读判断实质重复。双保险：关键词检索之外，再按标签维度查一次——用 memo_search 的 tag 参数（如 tag: 产业/高价值场景）或 tag_tree 看该标签下已有卡，覆盖"关键词没撞上、但同标签已存在"的漏判。判定：无命中→新建；完全重复→不再写、改指向原 memo；部分重叠→更新原 memo 正文；清单类一行提及→可单独建并从原处回链。回复必须写明查重结论（"查重：云端命中 X 篇（列名）或无重复"），不得用"已查重"三字敷衍。
5. 写作：按"卡片格式"与"写作规范"写成 1 条（一事一卡）；可用 flomo.memo_recommended、memo_search 调出相关旧记录，让新 memo 与既往上下文衔接。
6. 写云（新建，需授权）：把最终正文 + 首行标签段完整展示给用户，说明将写入你的 flomo 账号；经同意后调 flomo.memo_create（正文=memo 内容，标签=首行标签段，内容与展示一致）。写入前硬校验：带来源 URL 的 memo，其来源必须已实际 WebFetch/抓取成功并基于真实内容写作（未抓取/抓取失败/凭链接猜测 → 禁止写云，先补抓取）；无来源的纯想法 memo 不受此限。除非已明确约定"写卡直接落云"，否则必须停下等同意；本次不写云须明示。若第 4 步查重判定为"部分重叠"需更新，则本步不新建，计入第 8 步统一更新。新建成功后即完成，无需挂入任何索引卡（本项目不建索引卡，纯标签聚合）。
7. 复盘建议（收口后必做）：结合本轮所写 memo，思考是否有值得落地的事项，最多提两条建议——
- 常规建议：从 SKILL / AGENTS / 既有 memo / 标签体系 / 脚本工具 / 记忆惯例中，找最值得的一条可执行项（如新增/合并/精简某标签、沉淀某新卡、记某记忆）；没有就不硬提。
- 常规建议需覆盖"对既有 memo / 标签的更新、合并、删除"方向：复盘时扫一眼本轮的处理（查重、写作、提炼）是否实际催生了某条既有 memo 或某标签的更新 / 合并 / 删除需求（如查重判"部分重叠"需并入、某条既有卡被本轮内容更新或取代、标签需归拢或改名），有则将其作为常规建议提出来，落点指向具体那张卡 / 那个标签；这只是按本轮具体处理按需触发，不是主动评估卡间关系。
- 创新建议：若有主动增值方向（新卡型/新提炼模板/新流程机制）则提一条；没有就明确说"本轮无强创新点"，宁缺毋滥，不硬凑。
- 每条建议都要：给具体落点（哪张卡/哪条规则/哪个标签）+ 触发理由 + 明示执行方式并征询是否落地（已做完标"已落地"，未拍板标"待你决定"）。
- 输出极简：复盘建议只给必要的一句结论，不展开多行罗列、不加铺垫解释；未提的方向一律不列，避免浪费输出。
- 写卡落点默认按五种卡型逐项检查：复盘时若考虑"是否可以再写一张卡"，必须从五种卡型（事实/概念/框架/未竟思路/应用回环）逐一核对，指明建议写的是哪一种、触发条件是什么；不得用含糊的"写个方法卡/自定义卡"一带而过（若循环检查后确无可写、或某卡型本轮已写过，如实注明而非敷衍）。
- 对 SKILL 的改动遵循"更新/合并/删除"三态：更新=改表意不换原意或加新行；合并=两条内容重复或过近则并为一条（语义不丢）；删除=某条已过时/被取代/不再适用可明确判定时删行（须给理由）。先向用户说明改哪一行、哪种、为何，获同意后落地；不改则明示"本轮 SKILL 不改动"。
- 禁：不提"评估两张卡之间关系"类建议（卡的组织靠标签承载，卡间关系仅在查重/合并时按需判断，不以观察项或建议形式提前提出）。
8. 更新云端 memo（常驻最后一步，需授权）：这是收尾的维护步骤，不固定顺序前置——当第 4 步查重判定"部分重叠"、或你点名修改某条（改正文 / 补标签 / 改来源 / 去重）、或需要合并/整理标签时，走到这一步执行。做法：先用 flomo.memo_search + flomo.memo_batch_get 定位并通读原 memo；明确要改动的那一点；向用户展示改动前后；获同意后调 flomo.memo_update（保持首行标签段）。若本轮无更新需求，明确告知"本轮无 memo 需更新"即可，不必硬走。memo_update 是写操作需授权，绝不静默改云端；改前必须让你看清拟改动内容。删除 memo（纠错/去重出口）：当查重判定"完全重复且新建错误"、或你点名要删某条（误写/作废/内容被正确版取代）时，走此动作——flomo MCP 不提供 memo_delete 工具，所以经你确认后被删 memo 需由你在 flomo App 手动删除；先把拟删 memo 的序号、标签与正文展示给你并征得同意，删完在复盘里明示结果（含 memo id 与内容确认），绝不擅自判定删除即了事。

写作规范

- 结论先行：首句是卡片一句核心结论。
- 不设字数上限：正文长度由内容决定，够清楚即可，不强制拆卡（flomo 单条 memo 无字数硬限制）。
- 公式与数学：flomo 刻意不支持 LaTeX（官方为保证简洁拒绝公式排版，同不留 Markdown 语法/图片入正文），故不写美元符号定界符，数学公式一律用纯文本 / Unicode 表达（x²、√2、a/b、∑、μ、→）。中文为主，术语保留英文。
- 英文专名不硬译：直接用原文专有名词（Agent Harness、MCP、Skill），不硬译成中文打头。
- 成组数字用列表分行（flomo 无表格渲染，不用表格）：≥3 个并列数值指标（带同比/环比/占比/金额等口径）用 flomo 无序/有序列表逐行拆开，如 "- 营收 12.5 亿，+8%"，列清指标/数值/变化。
- 时序新闻去热（高时效必做）：来源是"本周发布/某模型上线"这类高时效内容时，memo 主语落在可复用的机制/概念/规格而非事件时间点，并留一个反时效持久锚点（归入既有主标签或抽象出可复用模式）；无法抽象的时效快照判不值得独立成 memo，并入上位或舍弃。
- 捕捉持久线索（去热的强化技巧）：遇"XX 新品泄露/发布"类新闻时，优先捕捉该厂商的命名/版本/代号体系这类低时效的持久线索（如 Anthropic 用文学体裁命名公开模型、内部开发代号跨批次换主题词）——这类体系知识比追单品时效快照更值得成卡，且能在未来反复复用。
- 复杂系统瓶颈口诀化（可复用写作技巧）：遇到复杂系统/产业瓶颈类内容时，主动尝试把核心障碍压缩成"三X一Y"式口诀——三个并列短板（低/贵/高/缺）+ 一个最痛点（高/缺/难/慢），如数据"三低一高"、算力"三贵一缺"、算法"三高一难"、应用"三缺一慢"。口诀化便于记忆、沟通与跨领域复用；提炼后可选拆出框架卡（见事实-框架双卡模板）。
- 事实-框架双卡模板（主题卡可选增强）：遇到主题/概念卡时，主动判断是否值得同时提炼一张可复用的方法论/框架卡——事实卡记"是什么"（该主题的事实、机制、案例），框架卡记"怎么分析"（抽象出的可复用分析框架，如算力组织三模式、实证-规范-实践三分法）。两张卡用双链关联（框架卡链接事实卡），标签同顶层不同细分（如 经济/学科史 + 经济/方法论）。判断标准：该主题的分析框架能否迁移到其他场景；能则值得拆出框架卡，不能则只写事实卡。
- 未竟思路卡（记进行时的思考线索）：专门记一个"尚未解决、未来值得回来处理"的开放思考线索，是这一体系里唯一"记进行时"的卡型。写卡时机：出现"这个我还想继续弄 / 没想清 / 待验证"，且值得未来拾起时。正文=一句话定界这条待办探究 + 目前已知（已推到哪）+ 下一步想弄清什么 / 触发条件；首行标签段含 `#未竟/主题`。一件事一张卡，不可把多条未竟思路装进一张清单卡（会退化回清单，违背一事一卡与去索引）。生命周期：后续遇相关进展回链本卡刷新状态——推进则更新、解决则记结论并关闭、放弃则记原因并关闭，关闭后不再累积，不因卡量增长而停留。判据：写卡时自问"这条是否要我未来还回来"，若不用就并入内容卡，不必立此卡型。与其他卡型区分：事实/概念/方法卡记"已完成的知识"（稳态），未竟思路卡记"未完成的想法进度"（进行时）；解决后的结论可长成独立知识卡。纯标签聚合下无索引，靠 `#未竟` 顶层标签 + 细分检索所有进行中的思路，不建索引卡。
- 应用回环卡（记知识被用起来之后的校验）：记录"把某张卡的方法/概念实际用到一个真实场景后，发生了什么、结论成不成立"，把笔记从"只进不校"变为能自我纠正。正文= 引用的卡（纯文本链接/标签）+ 这次用到的真实场景 + 结果（验证成/发现不适用/哪里要校准）+ 对原方法的校准。写卡时机：实际调用了某张卡的方法/概念处理真实问题之后。它与方法卡的区别：方法卡存"怎么分析"，应用回环卡存"这次应用的结果证据"；与事实卡区别：事实卡记现象事实，应用回环卡记"方法×场景"的验证证据。生命周期：可作为原方法卡的反馈校准（回链原卡补充结论），也可独立留存为经验。纯标签聚合下无索引，靠 `#回环` 顶层标签 + 细分检索，不建索引卡。
