# flomo 卡片笔记（云端）

> **本文件是唯一细则源。** 阅读顺序：先读「根本纪律」（三条）→ 遇到具体动作查「硬限清单」（编号 H1–Hn）→ 按「流程」执行 → 参考项查末尾「附录」。
> **硬限只在「硬限清单」定义一次**，全文其他地方一律只写编号（如「见 H7」），不重复表述。改动规则只改清单。
> 环境相关（路径、代理、端口、一次性实测记录）不在本文件，见 `ENVIRONMENT.md`。

---

## 一、根本纪律（三条）

这三条管住所有动作，任何时候不得违反。

1. **只读直接做，写云免确认**。只读工具（`memo_search` / `memo_batch_get` / `memo_recommended` / `tag_tree` / `get_*` / `memory_*` / webfetch / websearch）无需请示。写操作（`memo_create` / `memo_update`（含清空）/ `tag_rename`）一律免确认：抓取 → 查重 → 自检 EXIT=0 后直接写云，不展示等批。**收尾的「标签建议」同属写云动作，不得只提不做**：本轮提出的改名、归并、补挂、拆分须当轮执行完并复查生效，再写入结论。唯一例外是**多义合并**（两张卡都够格当主卡、谁并入谁影响信息组织）——此时停下问方向并给明确建议。
   - **禁止凭个人判断跳过写卡**：用户发链接即视为"需要写卡"；抓取成功且能提炼出任何事实、数据或观点就必须写云，不得以"内容单薄""不值得"为由跳过。仅抓取完全失败且无替代来源时方可跳过并说明原因。
   - **禁止把该做的事推回给用户**。粒度选择、拆分方案、格式细节等属执行者判断范围，自己定；只有多义合并方向才需要问。
   - **新建执行中合适的可自行决定、免确认写云**：复盘时认为值得建的新卡，经查重（两路并查，确保无同事件或高度重叠既有卡）且自检 EXIT=0 后直接 `memo_create` 落卡，无需等待用户逐条授权。判断"合适"的标准：主题独立、内容可支撑至少一个结论句、不与既有卡重复。执行后在本轮收尾报告执行结果（新建卡 id、标签）。**主卡本身的创建不算本条的新建执行**，它在「复盘结论」中报告即可。
2. **来源实实在在**。带来源的卡，其 URL 必须已真实抓取并基于实际内容写作。**抓取到的内容必须读回正文文件、逐条对照后才能落笔**——WebFetch 的一句话摘要、模型记忆、按域名或标题推演一律不算已抓取。抓取失败、空 SPA 壳且无外链可追时禁止写云。
3. **文档改动须立即推送并附真实 hash**。称"已提交 / 已推送"必须给出真实 commit hash，并以 `git ls-remote` 核对，不口头虚称。**文档（SKILL.md / AGENTS.md / 词表 / 脚本）改动完成 commit 后必须立即 push 到远端，再 `git ls-remote` 核对远端已含该 hash——不得停留在本地提交、不得等用户确认**（见 H25、H27）。

> **收尾强制三项（铁律，均不得等用户确认）**：① 卡正文无自指备注（H15）；② 文档改动后立即推送并附真实 hash（本条 + H25）；③ 每轮收尾强制清理残留临时文件（H27）。本项目曾因"卡片夹带内部待办备注""改动未推送成功""临时文件未清理"三度被判定严重事故 / 违规，故三项一并固化进细则。

## 二、硬限清单（唯一细则源，编号即引用点）

### A. 读写工具

**H1 · 读卡必须取全文，禁用截断内容。**
`memo_search` 与 `memo_recommended` 返回的 `content` 是**截断快照**（带 `content_truncated: true`，中间以"…[此处省略 N 字]…"占位），**只能用于"发现有哪些卡"**，不得据此判断某卡讲了什么、有多长、有没有违规、能不能当合并主卡。
凡要判断某张卡的**正文**（合并、覆盖更新、格式核查、复查自查），必须先 `memo_batch_get`（参数 `{"ids":[...]}`，可批量）取回**全文**。
> 事故根因：曾连续多轮把 `memo_search` 的截断内容当全文，导致写入的异事件内容长期"看不见"，合并与更新在错误认知上连续发生。

**H2 · 字数只认实测。**
字数一律取 `memo_batch_get` 全文实测长度或 `word_count` 字段。**严禁凭截断内容估算，严禁凭印象报"X 字 → Y 字"。** 无实测数据时如实写"未实测"。

**H3 · flomo 调用一律走脚本、逐次手动调用。**
统一 `python scripts/flomo_client.py <tool> --file <json路径>`（从文件读 JSON，避免引号被转全角）。每次查重、查树、写云、复盘的**每个关键词都单独调用一次并读该次原始返回**；禁止用内联脚本、`for` 循环、`&` 拼接等批处理把多次调用串成一次（批处理会掩盖单次结果、偏离逐次现查流程）。

**H4 · 返回值是包裹结构。**
所有工具返回 `{"content":[{"type":"text","text":"<内层JSON字符串>"}],"structuredContent":{...}}`，结构化数据在 `structuredContent`（如 `memos`、`id`）。**必须走 `structuredContent` 或解析 `content[].text`**，禁止直接 `result.get("memos")`（永远取不到，会造成"查重看似通过、实际没查到"而误新建）。`flomo_client.py` 已内置 `_result_memos(result)`。
人工查重与复盘**不得靠肉眼从打印文本里"看到"结果判断命中**，必须以程序解析结果为准。

**H5 · memo id 必须程序化取用。**
id 是 base64 风格长串，人工转写极易差一位（差一位即指向另一张卡）。写入 payload 前一律用脚本从查询结果取原始 id 字段生成请求文件，不手抄。

**H6 · 比对用签名，不用全文。**
flomo 存储会转义特殊字符（`>`、`|` 存成 `\u003e`、`\|`），本地与云端全文逐字比对必然不等。幂等与查重以稳定签名（**首行标签行 + 第二行概念名行**）为准——search 返回的 content 即使截断，前两行也始终完整。检索关键词要短：整行概念名含全角标点时全文检索常返回 0，用短核心词（概念名去标点的最长中文段、标签二级词、去标点全串前 8 字）逐一检索。

### B. 内容边界

**H7 · 单卡单事件。**
一张卡只记录**一个事件 / 概念 / 主题 / 企业**。多条目链接或一文多事件须按条目拆成多张独立卡。
**禁止跨条目汇总、禁止把多事件塞进一张卡**。反模式（一律视为违规）：进程卡、发布潮卡、产业格局卡、多条目盘点、日报/榜单/综述汇编。

**H8 · 同一事件的判定：以事件为准，不以主题为准。**
判定两篇材料是否同一事件，依据 **主体 + 动作 + 时点**三项是否同一（同一次发布、收购、财报、政策出台、事故、开庭）。
**仅"同属某领域 / 某主题 / 某条治理主线"不构成同一事件。**
反模式：把"分别发生在不同时间、由不同主体发布的多个政策/发布"因共享某主题而并成一张卡 → 产出 H7 所列的汇编卡。

**H9 · 同事件只留一张卡。**
同一事件（判定见 H8）只保留一张卡。无论新到几篇报道、拆出几个视角（商业、架构、评测、生态、财务），**全部并入同一张卡**，用 `memo_update` 覆盖式合并（重组织语言、消除重复、按逻辑重排）。严禁为"不同角度 / 补评测 / 补商业 / 补生态"新建平行卡。
反模式：同一事件连建"架构""商业""评测"三张卡。

**H10 · 合并只并事件本体，不并载体素材。**
合并 / 更新时只并入**属于该事件本身**的事实、数据与因果。报道中作为**论证素材**出现的举例、判例、类比、他方案例、延伸评论，**不得因"出现在同一篇文章里"而写入本卡**。
素材若本身构成独立事件且确有记录价值，另建独立卡，不得借合并塞入。
反模式：把"某法修订草案征求意见"的报道里用来举例的**司法判例**写进该立法卡。

**H11 · 合并后必须回读全文验收。**
任何 `memo_create` / `memo_update`（含清空）完成后，若属合并或覆盖更新，须 `memo_batch_get` 回读该卡全文，逐项确认：① 首尾同属一个事件；② 无载体素材混入；③ 无他卡内容串位；④ 字数与预期一致（取实测值）。
验收不通过则当轮修正。**禁止只凭"已写入 id"宣告完成。**

**H12 · 禁止关联卡片。**
卡片正文不得提及、引用或关联其他 flomo 卡片（"与已建卡的 XXX 形成…"、设"关联卡片"段落、引用其他卡 id / 标题 / 内容均在禁止之列）；禁止用 `linked_memos` 字段。每张卡独立成文，不依赖其他卡上下文，**不跨卡串联归纳**。

**H13 · 内容严格来自原文。**
原文是事件报道，就不写"方法论""启示"等原文没有的分析；原文是方法论文章才提炼方法论。原文没有的要点一律不写。滤除营销话术，保留事实、数据与因果链。

### C. 格式

**H14 · 卡片格式。**
结构：**首行标签段单独成段 → 第二行概念名称 → 空一行 → 正文**。缺少任一层级（空行、概念名称行）均视为格式违规，`validate_memo.py` 将报 ERR 阻断写云。

```
#标签/细分
<概念名称>

<直接写结论句，不带任何模板前缀>

要点：
- 要点一（依据）
- 要点二
```

- **概念名称**：简明概括卡片主题的**名词或概念**（如"马尔科夫链"）。不得写成"标题+副标题"或整句话。
- **结论先行（硬限，脚本 ERR 阻断）**：首段第一句直接写结论句，**禁止任何引导词前缀**——尤其不得把 SKILL 的条目名「结论先行：」原样回显进卡片正文，也不得写「一句话核心结论：」「一句话结论：」之类模板前缀。`validate_memo.py` 第 5.7 节「模板前缀回显检测」对「结论先行」四字连写（任意位置）与行首「一句话核心结论：」「一句话结论：」前缀均判 ERR 阻断写云。结论就是正文首句，不是"先声明结论在这"。
- **允许的结构标记只有 `要点：`** 与加粗/高亮/下划线/有序无序列表；其他纯说明性文字不得写入。
- **禁止模板指令回显（硬限）**：SKILL 中写给执行者的格式指令、条目名、占位符说明（如「结论先行：」「占位符必须替换」「直接写结论句」等）一律不得原样写入卡片正文。卡片只承载知识内容，不承载流程指令。任何形如「XX：」（XX 为 SKILL 条目名/格式词且非真实要点）的行首前缀均属回显，脚本将拦截。
- **占位符必须替换**：尖括号 `<...>` 是写给执行者看的，落卡时一律换成真实内容。
- **公式用 Unicode**（∑ μ →），不写 LaTeX 美元符。
- **单卡正文（含标签段）不超过 20000 字**，超出须精简，禁止超限写云。

**H15 · 无来源、无状态。**
正文禁止任何来源 / 作者 / 机构 / 报道 / 参考信息（**无论独立行还是句子形式**），也禁止任何状态 / 进展信息**独立行**。变体包括但不限于："来源：""作者与来源：""信息来源：""数据来源：""参考来源：""资料来源：""内容来源：""新闻来源：""原文来源：""引用来源：""来源链接：""参考资料：""参考文献：""报道：""报道信息：""报道来源：""状态：""当前状态：""进展状态："。
这些信息**一律直接删除**，禁止巧设名目保留，也禁止改写成“句子形式并入正文”变相保留。卡片是概念与事件的知识笔记，不是引用记录。
**尤其禁止一切面向自身的流程 / 备注 / 待办类内容写入卡正文**，无论是否独立成行——包括但不限于："本卡基于摘要写作""正文不可得""待正文可得后补抓并更新""待补抓""（正文不可得，先写摘要）"等内部状态说明与后续动作提示。这类内容属于执行者待办，不是卡片知识，写进 flomo 即污染知识库。来源信息（arXiv 编号、作者、机构，以及「据 X 报道 / 博客 / 仓库 / 页面」「代码见链接」等）**一律删除**，无论独立成行还是并入句子，都不得写入卡正文。

**H16 · 禁止卡片载体信息。**
卡片只写**概念 / 事件本身**，禁止交代"这张卡是从什么载体上抄下来的"。无论放在首段括号、要点句内还是行尾一律禁止，**无豁免位置**。
- 典型违禁表述：截图 / 截屏 / 录屏 / 屏摄、讲义 / 课件 / 幻灯片 / PPT / 板书 / 续页、字幕 / 批注 / 听课笔记、第 N 页 / 10–11/36 页、UP 主 / B 站 / 哔哩哔哩 / 直播间 / 课程记录 / 讲座、公众号 / 视频号 / 小程序 / 推文、"如图 / 见图 / 上图 / 该图所示"、带日期的"XX 课程讲义，定义 3"式出处括号。
- **载体上没有的信息直接省略**，禁止用"截图未展开""板书从略""页码待补"之类说法变相保留。
- **一切来源字样一律删除**：「B 站直播截图」「课程讲义第 9 页」这类材料载体，与「据沈阳市纪委监委消息」「新华社报道」「通报称」这类**事件自身的报道方 / 通报方**，**同等对待、一律不得写入卡正文**——卡片只陈述事件与概念本身，不署来源（见 H15）。

**H17 · 标签严格两级。**
合法形态只有 `#顶层/二级`（例：`#科技/安全`、`#思想/协调博弈`）。**三段及以上一律非法**（`#科技/安全/邮件认证` 不可）。
主题看似需要第三层时二选一：① 并入既有二级（邮件认证 / 钓鱼 / 攻击面本就含在 `科技/安全` 定义内，直接落 `科技/安全`）；② 在合适顶层下新建二级（仍是两级，免确认，但须先查近邻确认无既有簇）。
**宁可在二级内用正文细分，绝不下探层级。**
- 首行标签段，多个 `#标签` 用空格分隔，**每个都要带 `#`**（裸词不进标签系统）。
- **子标签必须带主前缀**：写 `#思想/协调博弈`，不裸写 `#协调博弈`（后者会建出独立顶层）。
- **顶层禁泛指词头**（`#概念/`、`#方法/`）；禁 emoji 与特殊字符；英文词用下划线（`#Apple_seed`）。

**H18 · 标签错配防御（不可跳过）。**
1. **核实主体所属**：定标签前确认主体的真实分类（饮料 / 食品 / 美妆 / 日化 / 科技 / 媒体等），不按模糊印象硬套。例：德芙是巧克力（食品），塞进"快消饮料"即违规。
2. **匹配事件本质而非事件载体**：按事件核心性质选标签，不按涉事品牌的行业大类硬套。例：德芙七夕暧昧文化争议本质是青年文化与婚恋价值观事件 → `#文化/青年文化`。
3. **不合内容绝不硬塞**：既有标签不精确匹配主题时必须新建更精准标签，不得以"语义接近"为借口硬套。例：主题是液冷服务器，即使存在 `#科技/算力硬件` 也不能塞——只有确认主题精确属既有标签定义范围时才复用。既不允许反问用户，也不允许"宁塞勿新"。
4. **具体当期主题 ≠ 纯概念筐**：`/方法论`、`/概念` 这类二级只收"研究怎么做"的元层面（框架、范式、通用方法）；某政策、某事件、某产品的当期解读严禁塞入，必须落到具体主题二级（无则新建）。
5. **新建前现查近邻**：新建顶层或二级前先 `memo_search` + `tag_tree` 现查确认无既有簇；**新建、重命名、合并标签一律免确认**；禁止为"能复用"而硬套既有标签凑数。

**H19 · 图片 / 截图输入只提炼内容，不记录载体。**
用户发来课程截图、直播画面、板书、PPT 页、公众号长图等图片时，图片只是**取材通道**，卡片只写概念本身（规则同 H16）。
图片糊掉或缺页导致某条信息无法确认时，该条**直接不写**，禁止用"截图未展开""板书从略"交代缺失。
定义、定理、公理各自独立成卡；同一定理的连续续页用 `memo_update` 覆盖式重组，**不做贴膏药式追加**。

### D. 更新与合并

**H20 · 更新必须重新组织语言。**
新内容融入既有结构，**合并同类要点、消除重复表述、按逻辑重排**；禁止在末尾机械追加要点（"贴膏药"式更新）。

**H21 · 取最新、删过时。**
用最新数据替换旧数据，删除已被覆盖的时间节点、旧统计与旧状态描述（伤亡数据只留最新节点，不留逐日旧值）。禁止为"保留历史"堆叠旧数据造成笔记膨胀。

**H22 · 更新前必先回读原笔记做格式合规。**
更新已有卡片必须先 `memo_batch_get` 回读原笔记（H1），按 H14–H17 检查（首行标签段、第二行概念名称为简明名词、无来源行与状态行、标签严格两级、不超 20000 字）。原笔记不合规时，必须在本次 `memo_update` 中**一并改到合规**，不得保留旧格式遗留。

**H23 · 清理前先经全文核对。**
清空前必须 `memo_batch_get` 确认是哪一张或哪几张（H1），避免误清本就合规的卡。
清空 = `memo_update(id, content=' ')`（必须**单空格**，空串被忽略）；卡片仍在云端，只内容被抹除，日后可重新写入。
清空会把该卡标签一并置空，**只挂在它上面的独占标签随之从标签树消失**——因此引用任何标签簇名前必须重新 `tag_tree` 现采，不得凭历史记录或旧日志引用。

**H24 · 素材保留。**
抓取原文、草稿、被替换的旧卡全文、请求 JSON 等中间文件，须保留**最近若干轮**（至少当次会话的全部轮次），**不得在同一轮收尾时即刻全删**；清理只清与近轮无关的历史文件。
> 事故根因：曾在上轮收尾时删掉当轮素材，导致下一轮无法回溯核对写入内容。

### E. 治理

**H25 · 文档改动走独立流程。**
技能文档（SKILL.md / AGENTS.md / 词表 / 脚本）的修订**一律等用户另行指令触发**，触发后走独立改动流程（commit + 真实 hash + **立即 push**）。
**push 是改动流程的必含终步，不是可选项**：commit 后必须立即 `git push` 并 `git ls-remote` 核对远端已含该 hash，不得停留在本地提交、不得等用户确认（曾因"改动未推送"被判定重大事故）。
**push 一律走 `scripts/push_skill.sh "msg"` 一条命令**（自动起隧道 + 清掉 `~/.gitconfig` 写死的 7897 代理 + 用 `gh` 凭据助手避开 `reg.exe` 黑名单 + commit + push + `git ls-remote` 校验远端）。**禁止手搓 bash / 临时拼 git 命令**——该流程的所有坑（代理、凭据、隧道、Qoder hook 触发 reg.exe）已收敛进脚本。
**写卡复盘的建议中严禁提议改动这些文档**——复盘建议的落点只能是 flomo 云端卡片本身。

**H26 · 本地与云端分工。**
笔记只在云端：卡片正文只存在于 flomo 账号，本地不落盘任何笔记内容。本地只留技能文档、配置与脚本。
不随仓库提交：`.mcp.json`（含 token）、`tag_tree.txt`（现采缓存）。
云端状态不进 memory：标签树、卡清单、已写入规则一律现查本文件或 `tag_tree`，不靠记忆。

### F. 收尾

**H27 · 收尾强制清理（不可等确认）。**
每轮 / 每会话收尾必须把**与近轮无关的残留临时文件**归档并删除，属强制流程，不等用户确认。流程：显式列名 → 打包 `.workbuddy/trash/temp-cleanup-<ts>.tar.gz` 并断言成员数一致 → 才删除 → 复核残留为 0。
- **清理一律走 `scripts/cleanup.py`（默认执行）**：`--dry-run` 只列名、`--verify` 只复核残留是否为 0。**禁止临时手搓 `_tmp_cleanup_*.py`**——保留项与排除清单（`_tmp_extract.py` / `tag_tree.txt` / trash 内旧包 / `D:\tmp` 他项目 `arxiv_test.xml`、`arxiv_vibe.xml`）已写死在脚本里，漏删/误删风险由脚本兜底。
- **不得删当轮素材**：与当前轮次相关的抓取原文、草稿、请求 JSON 等按 H24 保留至少当次会话全部轮次；清理只清历史残留，不碰当轮。
- 违反本规则（残留不清理）属严重违规——曾因 430 个残留文件未清被判定严重违规。

## 三、流程

按序执行，标「阻塞」的步骤未完成不得进入下一步。本节省略规则细则——动作涉及哪条硬限，只在句末标注「见 Hx」，细则一律查「二、硬限清单」。

### 1. 抓取
- 主通道 webfetch；SPA / 清单站补 `curl -L -A "Mozilla/5.0"`；同名对象按域名、作者、用途消歧。
- **抓回即读回**：抽取成正文文件后必须读回全文，未读回不得进入提炼与写作（纪律 2）。
- **预印本正文优先（阻塞）**：arXiv / bioRxiv / medRxiv / ChemRxiv / SSRN / OpenReview / ResearchGate 等，摘要页不作首选写作依据。先穷尽正文通道：
  - arXiv：`/abs/<id>` → `/html/<id>v<N>` → `https://ar5iv.labs.arxiv.org/html/<id>` → `/pdf/<id>`。
  - 其它预印本：走站内 Full text / PDF / HTML，或退作者主页、机构仓库（HAL、高校 repository）。
  - 被 SNI 阻断走域名前置（见 `ENVIRONMENT.md`）。
  - 正文得手时要点须落在**正文层级**（定理/命题编号与陈述、方法名、关键参数、实验结果与条件、附录结论）；只复述摘要泛泛表述不算正文写作。
  - 正文穷尽仍不可得：先 `search` 找正文级转述（作者博客、项目页、slides、引用综述）；仍无则**可据摘要写卡（唯一例外）**——要点严格限于摘要明示事实，禁臆测；面向自身的流程/备注一律禁止写入（见 H15）。

### 2. 验证（阻塞）
主体若为专业术语、数学概念、科学名词、机构/产品/模型/定理简称等，必须 `search` 现查标准名称与定义，不凭原文简称或图片特征臆测。查证项：标准术语（中英文）、命名来源/发明者与首提时间、关键参数。结果融入正文对应要点。抓取失败或无替代来源时跳过写卡并说明原因。

### 3. 提炼
滤除营销话术，保留事实、数据与因果链（见 H13）；图片/截图输入只提炼内容、不记录载体（见 H19）。

### 4. 定标签（阻塞）
1. 取标签树：按「附录 · 标签树本地留存」比数量——`tag_tree` 现采（`limit` 传 2000）与本地 `tag_tree.txt` 一致即直接用本地，不一致才现采并覆盖。
2. 命中既有簇优先复用，但只在与主题精确匹配时复用；不精确则新建更精准标签（见 H18）。
3. 避开纯概念筐：具体当期主题落到具体二级，无则新建（见 H18.4）。
4. 标签严格两级，禁三级（见 H17）。

### 5. 查重（阻塞）
- **两路并查**：`memo_search` 关键词扫 + `tag_tree` 列该主标签细分逐条比对（主标签检索常返 0，须退回关键词加逐条比对）。
- 每关键词、每标签检索单独调用一次并读该次原始返回（见 H3）。
- 判定三选一：两路均无命中 → 新建；完全重复 → 指向原卡；部分重叠/同事件 → 更新/合并原卡。
- **合并决策前必做三件事（阻塞）**：① 按 H8 判是否同一事件（三项同一才算，"同属某主题"不构成理由）；② 按 H1 对双方取全文再决定并什么/删什么；③ 按 H10 划清边界（只并事件本体，不并载体素材）。同时受 H7 反向约束（一卡不得塞多事件）。

### 6. 写作
按 H14 写 1 条。

### 7. 写云前自检（阻塞）
- 命令：`python scripts/validate_memo.py memo_body.txt`（支持 `--file`/`--content`/`--create`；JSON 自动抽 content，兼容顶层与 JSON-RPC 信封；读文件容忍 BOM）。
- **必须 EXIT=0（0 ERR）才写云**；任一 ERR 先改再写，禁把云端当草稿反复 `memo_update`。通过即 `memo_create` 写云，免确认。
- 质检覆盖：标签两级（H17）、结构（H14）、flomo 不渲染语法、正文脏标签、占位/生造来源、预印本摘要依赖、旧格式遗留（H15）、载体信息（H16）。
- ERR 阻塞，WARN 只提示。已知误报：标签段后空行 WARN——flomo 存储层自动插空行，本地单 `\n` 线上呈 `\n\n`，可忽略。

### 8. 复盘（写卡后必做，须现查）
- **三路逐一现查**：`memo_search` 关键词扫近邻、`tag_tree` 列同主标签细分、`memo_recommended`（**传本卡 id**，limit 20，只读校验，专补关键词搜不到的情况；不写 `linked_memos`）。前两者返回**截断**内容只用于"发现有哪些卡"（见 H1）。
- **本卡全文自查（先做，阻塞）**：按 H11 回读所写卡全文核对 ① 首尾同事件 ② 无载体素材混入 ③ 无他卡串位 ④ 实测字数；问题当轮修正。
- **新建合理性复查 / 错配核查 / 硬塞核查（先看）**：本卡是否应更新既有卡（H9）、标签是否塞进纯概念筐（H18）、标签是否与主体类别不符（H18）——是则当轮处置（合并 / 建具体二级 / 改正确标签）。
- **标签归并**：两卡仅命名不同、本质同类 → 当轮 `tag_rename` 归并（异步生效，禁据"读回未变"立刻判定失败逐卡兜底，会与后台撞车；稍后重采 `tag_tree` 或按旧标签 `memo_search` 复查，确残留才逐卡 `memo_update` 且首行标签 token 去重）。
- **标签补挂 / 拆分**：具体主题被宽簇吞掉 → 当轮新建二级或改挂（`memo_update` 只重写首行标签段、正文原样、标签 token 去重）。
- **跨卡合并**：见 H8/H9/H10/H11/H23，全流程免确认。完成后报告：主卡 id、合并后实测字数、被清空源卡 id、标签处理结果。**绝不声明"已合并两张卡"**（无 `memo_merge`）。
- **违规汇编卡拆解**：既有卡命中 H7 反模式须当轮处置：① `memo_batch_get` 读全文（H1）按 H8 切分独立事件；② 逐张新建独立卡（各走查重+自检 EXIT=0）；③ 历史沿革/背景若归属某既有主卡则回填（重组并入，不末尾追加）；④ 汇编卡内容全被覆盖且无独有信息则清空（H23），有独有信息则改记核心事件。拆解后现采 `tag_tree` 核对标签计数变化并报告。
- **确无近邻**：写明"已现查 tag_tree 与关键词，无需调标签或聚合"，禁只写"本轮无 memo 需更新"。

### 9. 更新云端
`memo_update`（覆盖式）或 `tag_rename` 直接执行（见纪律 1）。规则见 H20–H23。无待更新时明示"本轮无 memo 需更新"。

## 四、收尾输出（固定，逐项必填）

每轮写卡结束按序回复，各项都必须出现；无内容显式写「无」，禁止静默省略。

1. **复盘结论**：一句话写清三路现查结论（新建合理 / 应更新原卡 id=xxx / 需改标签），并说明跑了哪几路（`memo_search` 关键词、`tag_tree` 同主标签、`memo_recommended`）。
2. **本轮全文自查结果（必填，阻塞）**：按 H11 报告回读全文的核对结果——① 首尾是否同属一个事件；② 有无载体素材混入；③ 有无他卡内容串位；④ **实测**字数（写"实测"二字）。发现并修正了问题的须说明改前改后。**未做此项不得进入下一项。**
3. **标签建议**（一条，落点仅限标签改名、归并、补挂、调整）：
   必须针对本卡当前标签的实际问题——命名不准、与既有标签本质同类需归并、层级需调整、或未覆盖本卡核心属性需新建更精准二级。
   **本条是"当轮已执行项"而非待批建议**：给出结论时须同时报告执行结果（用了 `tag_rename` 还是逐卡 `memo_update`、动了哪几张、旧标签是否复查清零）。
   确实无需改动时直接写「当前标签命名准确、层级合规，无需改名 / 归并 / 调整」，不得编造，也不得只写「无」敷衍。
   严禁未来预测、假设场景或"未来可能出现什么标签"；严禁提议新建卡片（新建推荐由专门一项负责，二者不重复）；严禁提议改动 SKILL.md / AGENTS.md / 词表 / 脚本（见 H25）。
4. **新建执行**（0–3 条）：复盘时若基于本卡主题判定存在值得独立成卡的新建项，经两路查重确认无同事件/高度重叠既有卡，且自检 EXIT=0 后直接 `memo_create` 落卡（见纪律 1 第三款）。每条须在回复中报告：新建卡 id、标签、一句话内容摘要。若经评估后判断"暂不值得独立成卡"（内容单薄、与既有卡高度重叠、主题过窄或与主卡实质同一事件），可跳过不建，但须明确说明原因。**仅主卡本身的 `memo_create` 不算本条的新建执行**，它在「复盘结论」中报告即可。

```
新建执行：
- #顶层/二级 主题X（memo id=xxx）：[一句话论点，完整表述该卡的核心内容与价值]
- #顶层/二级 主题Y（memo id=yyy）：[一句话论点，完整表述该卡的核心内容与价值]
```

回复中禁止跨卡串联归纳（如"至此 X 谱系完整"），只就本卡陈述事实（见 H12）。

## 五、附录

### 写成功判定与防重复
- **判定依据唯一**：脚本退出码 0 且 stderr 出现 `[成功] 已写入 memo id=`。`flomo_client.py` 写操作后强制从 `result.structuredContent.id` 取 id，取不到即打印 `[失败]` 且退出码非 0；**退出码非 0 一律按失败处理，绝不重发**。
- **写前幂等（脚本层硬防护）**：`memo_create` 内置写前查重——按卡片签名（首行标签 + 第二行概念名，见 H6）检索，云端已有同签名卡时直接复用其 id（stderr 打印 `[幂等] 已存在正文相同的 memo id=`，退出码 0）。该保护不依赖调用方自觉。

### 工具与调用
- **可用 MCP 工具**：`get_daily_review` `get_format_guide` `get_tag_guide` `memo_batch_get` `memo_create` `memo_recommended` `memo_search` `memo_update` `memory_context` `memory_user` `tag_rename` `tag_search` `tag_tree`。（读卡两工具"截断 vs 全文"的分工见 H1。）
- **写操作只有三个**：`memo_create`（新建）、`memo_update`（覆盖整卡；清空也走本工具）、`tag_rename`（全库改标签名，异步生效）。
- **无 `memo_delete`**：flomo 不提供云端移除卡片 API，**物理删除只能用户在 App 内手动完成**；技能侧绝不调用删除，也不主动提示用户去删。
- **无 `memo_merge`**：跨卡合并靠"并入主卡（`memo_update` 重写）+ 清空冗余源卡（`memo_update` 空白）"两步组合（见 H9/H11/H23）；**绝不声明"已合并两张卡"**。
- **清空 ≠ 删除**：清空 = `memo_update(id, content=' ')`（单空格，空串被忽略），属常规写云动作，免确认（见 H23）。
- **参数**：`memo_create(content；format 可选 markdown / html，省略即纯文本)`；`memo_update(id / content)`；`tag_rename(old_tag / new_tag / max_memos)`（依赖 flomo Max 会员）。
- **禁 `linked_memos`**：`memo_create`/`memo_update` 均不得传 `linked_memos`（见 H12）；正文 `((memo_id))` 不被解析为链接。
- **正文防标签误识别**：flomo 扫全文把 `#xxx` 当标签，写前预判改写——`#8435` 写"issue 8435"、`≤#150` 写"第150位"、`C#/.NET` 用空格或"与"连接。**正文斜杠不预判改写**（`/xxx` 属正常书写）。
- 端点、鉴权、代理与推送通道见 `ENVIRONMENT.md`。

### flomo 富文本实测（与 H14 互补：H14 定结构，本段定渲染）
- **支持**：加粗 `**文字**`、高亮 `<mark>`、下划线 `<u>`、两级列表、空行分段。
- **不渲染**：标题、引用、代码块、链接、表格、图片。
- 表格只认三种真形态（分隔行 `|---|---|`、竖线包裹行 `| a | b |`、空格包围竖线成组 `a | b | c`）；紧贴文字的竖线（绝对值、集合势、条件概率 `P(A|B)`）属正常书写。

### 标签树本地留存
云端标签树留存本地**项目根** `tag_tree.txt`（首行 `# total=N`，按顶层分组列二级。`scripts/tag_tree.txt` 为历史遗留陈旧副本，已废弃、勿引用）。
每次定标签与复盘前先比数量：`tag_tree` 现采**必须传 `{"limit":2000}` 拿全量**（服务端默认 200 会截断；且 `limit` 须 ≥ 云端 total，否则 `tags` 被截断致 `len(tags) ≠ total`，无法据以重建）。
以 `structuredContent.total` 为云端标签总数，与本地首行 total 比对——一致才用本地 txt；不一致即现采并用 `structuredContent.tags` **整体重写**本地文件。**但不得只信本地首行的数字**（2026-09-26 实证：本地首行写 total=591，正文实际仅 590 个二级标签，云端已 593，仅比首行会漏判「内容落后」）：比对前须先核验本地「实际列出的标签数 == 首行 total」，任一不符即整体重写，重写后复核「列出数 == total」。**裸顶层标签**（tags 中形如 `投资/` 的有顶层无二级项）重写时单独成行 `投资/`，再另起一行列其二级（`投资/: 一级市场、…`），两者相加方等于 total。云端数量权威（`tag_rename`/清空都会改变）；本地文件属现采缓存，**不入库、不得 commit**。

### 脚本
- `scripts/flomo_client.py` — 直连 flomo MCP 唯一入口；内置写前幂等查重、`structuredContent` 提取、成功/失败判定。
- `scripts/validate_memo.py` — 写云前质检（H14–H17 等），EXIT=0 才可写云。
- `scripts/test_validate_memo.py` — 质检脚本回归用例。
- `scripts/sni_fetch.py` — SNI 被关键字阻断时域名前置取正文与 PDF。
- `scripts/git_tunnel.py` — GitHub 直连与注入代理都不通时的本地 CONNECT 透传通道（含 TLS 健康选路）。
- `scripts/push_skill.sh` — 文档改动后强制推送（H25）：起隧道 + 清写死代理 + `gh` 凭据 + commit + push + `git ls-remote` 校验，一条命令，禁手搓。
- `scripts/cleanup.py` — 每轮收尾强制清理残留（H27）：列名 → 归档 trash → 断言成员数 → 删除 → 复核残留 0，保留项与排除清单写死。
- `scripts/run_audit.sh` — 包好 Git 工具链、`SOUNDING_TMP` 与隧道后调 `audit_skill.sh` 自校。
- `scripts/audit_skill.sh` — 技能文档 linter。

### 维护约定
- 改动 `scripts/validate_memo.py` 后必须跑 `python scripts/test_validate_memo.py`（退出码 0 为全过）。
- 技能文档改动后跑 `scripts/run_audit.sh` 自校（已包好环境，勿手搓 `audit_skill.sh`）。
- 环境变化只改 `ENVIRONMENT.md`，不改本文件。
